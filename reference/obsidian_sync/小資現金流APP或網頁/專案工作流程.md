## 踩坑補充 2026-06-10

- `update-price-series.js` 原本硬寫死 `20260609`，導致隔天仍查舊日期。已改成用 `Asia/Taipei` 產生當日查詢日。注意：查詢日是 20260610 不代表官方一定已發布 6/10 行情；資料列仍以官方回傳日期為準，不能自行補假資料。
- `update-issuer-official-data.js` 每跑一次都會重複塞入同一句 limitation，造成每日 Actions 可能產生無意義 diff。已改成先清掉同類 limitation，再寫入單一最新描述。
- GitHub CLI 原本的 `shaino0807` token 失效，`gh auth login -w` 在 Codex shell 中沒有穩定顯示 device code。最後改用 GitHub OAuth device flow 取得 code，使用者手動授權後再用臨時 token 建 repo、push、啟用 Pages。
- 第一次 GitHub Actions 失敗是因為 push workflow 時 Pages 還沒啟用，`actions/configure-pages` 查不到 Pages site。啟用 Pages 後 rerun 即成功。
- GitHub Actions 會自動 commit 更新後的 `webapp/data/etf-database.json`，因此本地後續 push 可能被拒絕 `fetch first`。處理方式：先 `pull --rebase`，保留本地未提交變更，再 push。
- GitHub Pages 是靜態環境，沒有 `/api/database-status` 或 `/api/update-database`。公開頁若沿用本機 API 呼叫會造成 404 console error。已在 `location.hostname.endsWith("github.io")` 時跳過伺服器更新 API。
- GitHub Pages 會向站台根路徑要求 favicon；若只靠 `icon.svg` 但沒宣告 `<link rel="icon">`，會產生 favicon 404。已在 `index.html` 補上 SVG favicon link。
- Service Worker 會讓遠端頁測試誤讀舊的 `app.js`。每次修公開前端資產後要 bump `sw.js` cache name，測試時也要清掉舊 service worker/cache 再判斷是否真的修好。
- 遠端 smoke test 需同時看 HTML 200、JSON 200、console errors、Network 4xx、手機 `bodyOverflow`、完整報告解鎖後的表格列數；只看首頁 200 不代表部署成功。

## 踩坑補充 2026-08-13（人工檢視、隔離 smoke 與 Pages 發布）

- `smoke-test-page.js --serve` 原本直接把 `process.argv[2]` 當網址，導致 `--serve` 被送進 Chrome 而出現 `Cannot navigate to invalid URL`。CLI 參數應先區分非 `--` 的位置參數與選項，再決定預設網址。
- smoke 固定使用 `5188` 且繼承既有環境時，可能連到另一個本機服務，出現 `CUSTOMER_DATA_KEY 尚未設定`、`/api/events 400`、`/api/reports 400` 或 `/api/market/refresh 500`。這些不是前端回歸證據；整合 smoke 應使用隨機埠、臨時資料目錄、臨時密鑰與明確 `SMOKE_TEST=1`。
- 測試環境若繼承 `GITHUB_ACTIONS_TOKEN` 或 LINE 回覆設定，頁面開啟可能觸發外部 Action 或真實 LINE 回覆。隔離 smoke 必須明確清空 `GITHUB_ACTIONS_TOKEN` 並設定 `LINE_REPLY_DISABLED=1`。
- 「尚無實際帳」不能用數值 0 呈現。`$0` 與預算差額會讓使用者以為已經完成實際記帳；應以 `hasActualEntries` 控制顯示，未知狀態用「—／尚無實際帳」，而不是假數值。
- 只依賴 `summary.counts` 判斷實際帳會讓舊摘要失效；舊資料可能有 `entries` 卻沒有 `counts`，應以明細長度作為相容 fallback。
- 遠端排程可能在本機提交後新增 ETF 快照。本輪 push 前 `origin/main` 已多出 `db5f1c6`、`73fff9e`，先確認都只改 JSON，再 rebase 本機 commit；不能直接 push 或 force push。
- Pages workflow 成功後又產生 `2e6273d` ETF 自動 commit。收工前必須再次 fetch、確認只改 `webapp/data/etf-database.json`，再 `git merge --ff-only origin/main`，避免本機落後。
- GitHub CLI token 失效不代表 Git HTTPS push 一定失敗；本輪 `gh auth status` 失敗，但 Git Credential Manager 仍成功 push。CLI API 權限、Git push 憑證與公開 GitHub API應分開驗證。
- PowerShell 變數名稱不分大小寫，`$home` 會碰撞唯讀系統變數 `$HOME`。驗證腳本應使用 `$pageResponse`、`$healthResponse` 等工作專用名稱，不能重用系統變數名稱。
- 公開 Pages 驗證若直接跑會建立報告的完整 smoke，可能在 Render 留下測試資料。未明確授權外部資料寫入時，發布驗證應使用唯讀 HTTP 200、公開資產內容標記與 `/api/health`；需要完整線上流程時再建立可清除的受控測試資料。
