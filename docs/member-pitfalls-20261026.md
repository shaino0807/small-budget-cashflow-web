# 2026-10-26 會員權限與導覽踩坑

對應[收工紀錄](member-closeout-20261026.md)。本紀錄區分已修復問題、驗證方法與尚待改善項目，不包含私人會員資料。

## 1. 可程式點擊不等於使用者看得到

原導覽 `.app-tabs` 被 CSS 放到畫面外並縮成 1px。無障礙樹仍找得到按鈕，程式點擊也可能成功，但真人找不到後台入口。

修復：登入後提供可見的固定導覽；在桌面及 390／320px 檢查實際位置、尺寸、可點擊範圍與捲動後入口。驗收必須結合真實畫面與操作，不能只靠元素存在。

## 2. 網址、畫面與返回歷史不同步

原本切換畫面沒有更新 URL，網址仍可能寫著 `adminView`，實際卻停在其他頁面。

修復：畫面切換同步 URL／history，處理重新整理、上一頁／下一頁、無效路由及拒絕存取後的實際位置。

## 3. 權限尚未載入就決定導向

非同步權限刷新尚未完成時，用舊值判斷完整報告資格，可能把管理員或已開通會員送到升級頁。固定升級 CTA 也造成相同困惑。

修復：導覽等待共用的權限請求，最後一次導覽意圖優先；CTA 依資格顯示「開啟完整報告」。後端仍必須再次授權，前端判斷只負責體驗。

## 4. 暫時故障被誤認為未開通

服務 5xx／網路失敗不能視為會員被撤銷，也不能沿用舊私人報告或無限自動重試。

修復：401／403 與傳輸錯誤分開處理；短暫錯誤保留登入身分但清除私人報告快取，顯示可重試訊息。測試要同時涵蓋合法未開通、登入逾時、撤銷及服務錯誤。

## 5. 手機最小寬度與固定導覽互相影響

320px 的固定最小寬度加上捲軸會溢出；固定導覽若不考慮頁首高度，可能遮住內容。

修復：最小寬度採 `min(320px,100%)`，以頁首實際高度調整導覽偏移；按鈕至少 44px。桌面瀏覽器手機寬度驗證不等於實體手機驗證。

## 6. 「狀態」混用兩種結果（待改善）

報告列表優先取 `stockSafety.level`，不存在時才取 `report.status`。因此「現金流」報告也可能顯示 yellow，而報告分數標籤是「穩健」。

現有燈號：green＝可以開始但先小額；yellow＝可以學但不要買太多；red＝先補現金流；black＝貸款或生活費壓力太高。這是報告儲存時的規則結果，不是付費資格或即時帳號狀態。

建議改成中文並分開「財務健檢結果」「投資安全燈號」；另保留「追蹤」new／contacted／converted／closed。這次只記錄，未修改 UI 或歷史資料。完成率 371.4% 的統計口徑也待釐清。

## 7. 管理員與付費會員不能混為一談

管理員角色與完整功能開通是不同權限。會員開通／撤銷不能變更管理員角色；一般客戶即使拿到 adminView 網址，也必須被後端拒絕存取。

既有角色回歸及未登入 401 證據只證明所測路徑，不等於完整資安稽核。下一階段仍需檢查跨會員存取、Session、輸入攻擊面與依賴漏洞。

## 8. 收工文件不能引發重複部署

Pages workflow 監聽 main push；Render 跟隨 main 並等待檢查通過。不能為了補文件就假設推送不會影響發布，也不應只靠 `[skip ci]` 猜測所有服務行為。

本次把兩份文件推到既有工作分支，不合併 main、不觸發 workflow_dispatch。先讀回 repo／Actions／Render／公開檔案，再決定是否需要部署。

最新排程從舊程式 SHA 啟動，過程產生新的 ETF 資料 commit 再發布 Pages；workflow head SHA、repo main、公開程式及資料批次必須分開記錄。來源步驟 skipped 不可記為 pass，HTTP 200 也不能代表資料完整。

## 9. 權限限制與檔案不存在要分開診斷

PowerShell 讀 G 槽先回 Access denied，不能因此斷言 Vault 不存在。改由既有 Obsidian MCP 讀取，確認主要 Vault 存在；指定駕駛艙則由連接器確認不存在，所以沿用 Codex Logs。

GitHub CLI 受網路沙箱影響時，也不能直接判定認證失效；在已授權的連線範圍重查即可。全程保留 dirty worktree，不用 reset、廣泛 stage 或清理測試目錄來取得「乾淨」狀態。
