## 已實作規則

| 身分 | 功能 |
| --- | --- |
| 訪客 | 具有明確標示的虛構範例；個人操作需 LINE 登入 |
| 免費會員 | 自己的基本記帳、收支摘要、基本健檢與資料匯出 |
| 已開通會員 | 上述功能加詳細穿透、配息壓力測試、配置與長期規劃、月曆及列印 |
| 管理員 | 完整功能、會員開通／撤銷與操作紀錄、客戶報告管理 |

完整功能綁定會員帳號，持續有效至撤銷、沒有自動扣款，也不限定單份報告。新建報告及第二個登入工作階段沿用同一權限。刪除單份報告不會刪除會員權限。撤銷後，下一次受保護 API 請求拒絕完整功能；基本記帳仍可用。

已產生的截圖、下載與列印無法遠端收回。前端於切回視窗、頁面顯示、進入完整功能、列印及可見頁面每 30 秒重新核對權限；取消權限會清除本頁的規劃與穿透暫存。

## 管理操作

1. 正式啟用前，由本人完成 LINE 登入，取得頁面下方顯示的會員編號。
2. 經核對帳號與目標資料庫，維運人員才能設定第一位管理員。需明確設定 `CUSTOMER_DATA_DIR`，沿用服務已有的資料加密金鑰、pepper 及管理設定，不把秘密貼到聊天、筆記或 Git。
3. 設定程序：`node webapp/scripts/bootstrap-member-admin.js <已核對會員UUID> --confirm-first-admin`。只允許已有會員且資料庫尚無管理員的情況，交易內檢查避免重複初始化。沒有對外開放的自助升權 API。
4. 管理員用原 LINE 帳號登入，開啟後台，依會員編號查詢，填寫操作原因，再按開通或撤銷。可查看對象、操作者、時間及原因。
5. 已開通狀態與人工核款／試用等原因保存在權限紀錄；不建立假付款訂單，不把開通狀態當作付款證明。

正式啟用上述程序與資料庫遷移須另行授權；本輪只對隔離測試資料執行。

## 後端與資料相容

- 新增 `member_access`、`user_roles`、`member_access_audit`。會員權益獨立於報告的保存期限；舊 `report_entitlements` 與付款資料保留。
- 已歸戶且有已付款完整報告的舊會員採新增、不覆蓋的遷移。人工撤銷紀錄不被重開資料庫或舊權益再次覆蓋。未歸戶報告以登入後提供原編號與存取碼的方式認領；已有其他擁有者時拒絕。已過保存期限的報告不能透過認領恢復。
- 個人 API 取消匿名操作；後台必須是後端確認的管理員登入工作階段。網址參數、前端變數或原管理金鑰不能單獨授權。
- `/api/users/me/access` 讀取會員權益；`/api/admin/members` 查詢會員；`/api/admin/members/:id/access` 開通／撤銷及讀取歷程；`/api/reports/claim` 認領舊報告。
- `/api/reports/full` 每次檢查登入與完整功能後才執行後端規劃引擎。`member-report.js` 不在公開打包白名單。免費會員讀取已保存報告時只回傳基本報告欄位與自己的輸入；前端 JSON 匯出同樣限制。
- 詳細穿透工作建立及進度端點都需完整權限，並核對工作擁有者。官方來源原有日期、估值、待更新及缺口規則未放寬。
- 規劃引擎沿用既有規則式計算，將假設顯示於報告。計算搬到後端不等於評分、配置建議或金融資料品質已獲認可；這次沒有新作金融方法驗收。
- 舊模擬金流流程仍有相容性測試；客戶畫面採人工開通，本輪未接通正式金流。退款、核款及權限判斷需依各自紀錄處理。

## 發布前仍需處理

正式啟用前先備份資料庫並在副本驗證遷移，再設定本人管理員；發布需核對 main、Pages、Render 的實際版本。回復程式時不能以刪除新權限表當回復手段；舊程式不具備這次會員保護，需先停止對外存取，不能直接當作安全的降版。
