# 本輪踩坑與續作方法

| 踩坑／證據 | 後續做法與限制 |
| --- | --- |
| 同版兩次來源驗收失敗代號不同：首次四檔，第二次改 00992A | 保存每次真實結果；先定位請求與耗時，再決定局部修復。尚未證明根因，不能靠一直重試直到綠燈證明穩定。 |
| 單元與容器測試通過，但官方來源仍逾時 | 程式、來源／日期、目標環境與公開操作分開列結果。74 項通過不等於資料最新完整，也不等於 60／120 秒 SLA。 |
| 五檔舊快取原本可能繞過待更新決策 | 待更新判斷放在快取之前；同步初始化結果，全待更新立即結束。混合保留未知曝險及原投入分母。 |
| 缺資料容易被誤讀為不支援或零重疊 | 五檔只標「基金資料待更新」；保留原 87 檔分類，不新增黑名單、不縮小支援清單來過測。 |
| 進度百分比容易被當成資料正確率 | 明示已處理包含待更新；百分比不能代表官方資料已全部驗證。 |
| 沙箱持久化測試有五項失敗；授權環境 Node 24 重跑通過 | 保存兩份輸出與環境差異，不改產品快取規則迎合沙箱。只憑重跑不能斷言精確根因。 |
| 瀏覽器原介面無法連線；本地測試服務另需允許隔離測試 Origin | 使用可用 CUA 備援取真實畫面；Origin 設定只限測試程序，不改正式安全限制。 |
| 本機手機尺寸與 CI 綠燈容易冒充公開手機驗收 | 圖片標示本地／候選、尺寸與版本；390×844 是模擬，未測實體手機。發布後仍需公開流程驗收。 |
| repo main、候選分支、Pages、Render 可能版本不同 | 發布前逐一比對 commit、Actions、live deploy 與公開 HTTP；已有同版部署便不重送。此次 be8386c 線上，b1c0406 候選。 |
| 執行中斷後超過原定 60 分鐘窗口 | 先對帳已送操作、保存 checkpoint。新收工授權不重置原修復預算，也不把失敗驗收改成成功。 |
| 指定 Vault 駕駛艙不存在、沙箱 G 槽出現拒絕讀取 | 區分權限與不存在；以既有 Vault 連接器及 Codex Logs 延續，不自建替代 Vault。讀回僅證明本地筆記可取用。 |
| 本人也看不到完整報告，現行付款入口未設定 | 下階段討論登入身分＋後端權限，管理員可查看及手動開通；先做報告範例盤點。尚未實作，不以 localStorage 改值當正式開通。 |
