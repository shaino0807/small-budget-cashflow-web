# LINE 真人驗收回饋：明細與語音釐清

## 問題與修正

- 未出帳消費截圖只有月日，既有日期安全規則把缺年份的整筆排除，回覆又把所有原因合併為泛稱，造成看似完全沒有辨識。改為逐列保留安全的商家名稱、金額、月日與費用分類，逐項顯示缺欄；信用卡商家消費仍為支出，真正繳卡費／轉帳仍需釐清。
- 缺少年份或幣別的完整交易列，保存在原有加密、30 分鐘逾期的待補資料中。使用者可回覆「圖片補充 2026 台幣」（填實際年份與幣別），伺服器重新核對日期、重複項目及整批完整性，再提供確認入帳。補充不重新下載圖片或呼叫 OpenAI，不使用當前年份猜測。
- 未知商家保留可見名稱並列其他支出，不從截斷的英文店名猜商品。分類涵蓋停車、鍋物、電信、產險、Uber Trip 及手續費。
- 語音數字正規化原先只有「停車」，漏掉「停車費」，因此「停車費一百八」未轉為 180；「停車費花一百八」則由「花」規則命中。已補齊並保留 ETF 代碼與金額分隔測試。
- 「今天花晚餐，還今天花停車費一百八」有兩個用途但只有一個金額。現在明確回覆已辨識 180 元，請確認是哪一筆或是否合計，不把晚餐默默併入或漏掉。缺日期、用途、金額分別說明；仍不猜、不先寫入部分帳目。

`node webapp/scripts/run-ledger-regressions.js --browser` 通過：12 項非瀏覽器測試，及 390×844、1440×900 瀏覽器測試。

新增／擴充測試涵蓋：

- 八筆商家列缺年／幣別時仍顯示，補齊後合計 5,036，分類正確，確認前帳本為零。
- 取消、撤銷同意、關閉正式開關、非一對一聊天、逾期、非法年份日期、非台幣、隱私欄位、繳卡費與圖片重傳均無法繞過入帳保護。
- 補充年份幣別零次額外辨識 API，已入帳圖片重傳在 OpenAI 前攔截。
- 停車費中文數字、缺欄精確回覆、多用途單一金額、多筆金額與 ETF 代碼不混淆。

日誌：`webapp/reports/clarification-full-regressions.log`。測試使用模擬回應與無私人卡號的文字案例；没有重新傳送使用者的真實截圖，也沒有新增付費 API 呼叫。

## 驗證邊界

這些結果證明伺服器解析、釐清與入帳流程的本機回歸，不等同改版後真實 OCR／語音模型已再次驗收。新提示下的真實辨識仍須在正式 LINE 由使用者重測；付費合成 API 額度先前已使用完，本次未追加。

發布時須核對 CI、Render 實際部署版本、圖片／語音開關維持啟用；不得以本機測試代替上線證據。原有設定、加密金鑰、客戶帳目與未提交 AGENTS.md／docs/agents 變更保留。

## 發布過程中的測試環境修正

- PR #4（82b4f40）及 PR #5（28689e1）完整 CI 分別通過。主線 run 34729280532 首次停在測試 API 啟動，重跑一次後全部非瀏覽器測試通過，卻停在 Chrome DevTools 啟動。未跳過或刪除檢查。
- 舊 API 等待約 6 秒、Chrome 等待約 10 秒，且沒有最後錯誤原因。改為有界的 30 秒啟動等待、每次請求逾時及程序提前退出檢查，保留所有功能／畫面斷言。
- 發現另一個可重現的測試風險：隨機 API port 範圍包含 6000，Node fetch 會直接回報 bad port。健康檢查改用與其他 API 測試相同的 Node HTTP，避免有效本機連線被 fetch 埠限制攔截。原 CI 沒記錄所選埠，不能斷言該次失敗就是 6000。
- 「我今天花一百八塊錢」「請幫我記帳今天花180元」也納入缺用途案例，避免把口語助詞當用途。
