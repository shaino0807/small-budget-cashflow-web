# 本次踩坑與防止復發

| 現象 | 原因／證據 | 修正與防護 |
|---|---|---|
| 已說年月日仍被判缺日期 | 原正規化只轉中文金額，未處理「二零二六年九月十三號」 | 日期先正規化，逐筆保留年份；測試中文、數字、空格、跨年與不存在日期 |
| 一次說兩筆遭拒絕 | 語音路徑原本限制單筆 | 按標點及明確用途分段，一次預覽與確認；缺一筆資料則整批不先寫入 |
| 晚餐與停車共提到一個 180 | 金額存在，但歸屬不明 | 說明需釐清哪筆金額，不可回覆「完全沒有金額」或自行拆分 |
| 圖片能讀商家卻全部拒絕 | 年／幣別缺漏與完整性警告混用 | 保留可讀明細，警告用固定原因碼；裁切、未知警告仍阻擋 |
| 回覆年份被當成新帳目 | 補充路由未優先延續圖片草稿 | 加密保存待補草稿，自然語句先套用原草稿，不再送圖片辨識 |
| 台幣產品反覆追問幣別 | 未標示幣別採嚴格必填 | 依本次產品決策，未標示預設台幣並告知；明確外幣仍阻擋，不換匯 |
| 成功入帳只有文字，缺乏明確完成感 | 圖片補充成功走獨立回覆分支 | 附共用 Flex 月統計，從資料庫讀實際入帳月份；保留文字明細 |
| 手機 CI 偶發標題不符 | 輸出證明仍顯示「官方資料庫已更新」通知 | 有上限等待通知自然結束，保留原標題斷言，不放寬驗收 |
| 舊客戶 API 測試偶發失敗 | 隨機測試埠可能命中 fetch 禁用的 6000；原失敗無埠證據，不能斷定唯一原因 | 調整埠範圍並加入診斷，保留付款／dispatch 斷言 |
| 綠色 CI 被誤當成已上線 | Repo、Pages 與 Render 是獨立狀態 | 查精確 SHA、Render live、公開檔案與私密路徑、健康開關；模型真人驗收分開列 |
| 收工推送遭非快轉拒絕 | 遠端自動更新 ETF 資料 | fetch 後確認範圍，快轉或正常合併，不強推、不覆蓋既有變更 |
| 使用上限中断驗證 | 自動核准審查因使用上限拒絕最後網路命令 | 留存已完成狀態，續工補驗；不以其他通道繞過拒絕 |
