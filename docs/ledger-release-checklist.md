# 記帳修正版發布驗收

2026-09-12：10 項非瀏覽器本機回歸通過，手機／桌面關鍵頁面經 CUA 補驗；完整 CLI 瀏覽器套件尚待執行。以下正式環境項目全部待驗，不得以本機結果或服務 ready 狀態代替。發布、圖片外部辨識與測試帳號寫入須先取得對應授權。

## 發布前

- 執行 `node webapp/scripts/run-ledger-regressions.js --browser`，保存結果與準備發布的 Git SHA。
- 核對 GitHub 回歸工作成功，Pages 發布依賴該工作；確認 Render 採用 Blueprint 的 `checksPass` 設定。手動部署也須使用已有通過證據的版本。
- 既有 ETF 資料更新會建立 `[skip ci]` commit。Render 對沒有 CI checks 的 commit 不會自動部署；若最新 commit 是這類資料更新，須先對預定版本執行回歸 workflow 並核對 SHA，不可直接假設 Render 已跟上 main。
- 本機未具備 Render CLI，Blueprint 尚未經 CLI 驗證；套用前執行 `render blueprints validate render.yaml` 並檢查 Blueprint 預覽。
- 先驗證後端完整設定 API，再切換前端；確認資料備份與回復版本。圖片功能預設關閉，另行核對開關、告知頁面與模型設定。

## 真正 LINE 與網站

使用獲准的測試帳號及合成明細，逐項記錄時間、網址、後端版本、前端版本、預期／實際結果與證據位置。

- 長訊息：原始案例 22 筆（21 筆付款合計 54,733、薪資 68,981）完整預覽，確認前帳本不變；有不明行則列出原因，修正後才整批確認。信用卡帳單與逐筆消費是否重複須先核對，不能直接當作正式支出總額。
- 取消、重送與重複確認：不得多入帳。整批回滾由本機故障注入測試證明，不在正式資料庫製造故障。
- Render.com 230 元顯示支出，正式帳目、回覆卡片、月統計一致；真正 ETF 買入仍屬投資。
- 修改年度預設、套用 12 個月份，按「儲存全部變更」並等待成功；關閉網站、重新登入及另一裝置讀回一致。
- 刪除全部 ETF、儲存後重新開啟，部位仍為空；模擬網路中斷時顯示失敗且保留修改，恢復後重試成功。
- 圖片：完成告知與同意，辨識合成圖片，逐筆核對後入帳；分別重傳待確認及已入帳圖片，均須攔截。
- 同日期、同金額（包含不同類型）須提示疑似重複；信用卡繳款、自己帳戶間轉帳、不清楚的日期／年份／金額均須要求釐清。
- 網站讀到新資源（快取版本 `cashflow-map-v31`），LINE webhook 指向已驗證的後端；健康檢查成功不能代替以上行為驗收。
- 在手機與桌面確認第六步的同意錯誤不重疊、勾選後清除；聯絡卡片文字可讀；來源日期卡片不溢出；長條滑入畫面後才展開。舊快取頁不能作為修正版驗收證據。

## 完成判定

每項結果只能標記「通過／失敗／未執行」，並附實際版本。任何失敗或未執行項目都不得宣稱客戶端已完整驗收。既有錯帳須另行核對並修正原帳目，避免新增一筆造成重複。
